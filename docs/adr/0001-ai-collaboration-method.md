## 상황 (에이전트 정리 — 사실 여부를 사용자가 확인)
- 이전 프로젝트에서 문서 작업에 7주를 쓰고 School CRUD 하나가 나왔다. (cbl §8)
- 조사 전에 답을 정했다 (`curriculum` 필드, 선착순 동시성). (cbl §8)
- 긴 세션은 컨텍스트가 압축되어 이전 내용이 유실된다. 이번 기획 세션에서도 실제로 일어났다.
- 이 프로젝트의 목적은 취업 포트폴리오다. AI를 쓰되 사람이 주도했다는 근거가 남아야 한다.

## 선택지 (에이전트 정리 후보)
- **A. 즉흥 지시** — 장점: 빠름. 단점: 근거와 맥락이 남지 않고 세션 간 이어지지 않는다.
- **B. 단일 세션 + AGENTS.md 상시 규칙** (이전 방식) — 장점: 단순. 단점: 컨텍스트 유실, 코드를 쓴 세션이 스스로 리뷰해 위반을 못 찾는다.
- **C. spec 계약 + 역할 분리 세션 + 사람 게이트** — 장점: 상태가 파일에 남고 리뷰가 독립적이다. 단점: 핸드오프 오버헤드, 문서 증가 위험.
