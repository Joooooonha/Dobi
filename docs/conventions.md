# conventions — 매번 이렇게 한다

현재 유효한 규칙 목록. 이유는 ADR에 두고 여기엔 규칙과 한 줄 이유만 적는다. 분량 상한 80줄.
**규칙은 필요해질 때 추가한다.** 코드를 쓰기 전에 미리 짓지 않는다. 선택이 갈렸던 규칙에는 ADR 번호를 단다.

## 커밋
- Conventional Commits, 영어: `<type>: <subject>`
- type: `feat` `fix` `refactor` `perf` `test` `docs` `chore`
- subject는 소문자 시작, 명령형. 한 작업 = 한 커밋.
- 이유: 이력만 보고 변경의 성격을 구분한다.

## 브랜치 · PR
- `main`에 직접 커밋하지 않는다. 작업은 `feature/<대상>`에서, spec 하나 = 브랜치 하나.
- PR 본문에 해당 spec의 DoD 체크리스트를 붙인다.
- merge는 사용자만 한다. push는 사용자가 지시할 때만 한다 (머신을 옮길 때는 사용자가 push를 요청한다).
- 이유: 검증되지 않은 코드가 `main`에 섞이지 않게 하고, 어느 변경이 어느 spec에서 나왔는지 추적한다.
