# 검증 세션 (대상: $ARGUMENTS)

`AGENTS.md` §1 절차로 시작한다 (읽기 → 4줄 브리핑 → 사용자 확인). **코드를 쓴 세션과 달라야 한다.** 같은 세션이면 시작 전에 사용자에게 알린다.

## 이 세션을 맡는 때
- 상태 `Verifying`, 담당 `검증`.
- 끝낼 때: 통과 시 담당 → 사용자(`Done` 판단). 위반 시 상태 → `In progress`, 담당 → 개발.

## 역할 확인 (시작 시 첫 단계)
1. `SPEC.md`에서 `현재 단계 담당`이 **검증**인 행을 찾는다. 인자가 있으면 그 행이 여기 해당하는지 확인한다.
2. 해당 행이 없거나 담당이 다른 세션이면 **작업하지 말고 멈춰서 알린다.** ("이 작업의 담당은 ○○입니다. `/○○`로 시작하세요.") 사용자가 지시하면 예외다.
3. 해당 행이 여러 개면 어느 것인지 사용자에게 묻는다.

## 역할
구현을 옹호하지 않고 위반만 찾는다. 문제가 없으면 없다고 말한다.

## 하는 일
- DoD를 하나씩 직접 실행해서 증거(명령 출력, 화면 확인)를 남긴다.
- spec의 '범위 밖'과 `AGENTS.md` §4 위반 여부, spec에 없는 파일·기능·의존성이 생겼는지 확인한다.
- 테스트가 실제로 실패할 수 있는 테스트인지 본다. 통과만 하는 테스트를 찾는다.
- 사용자 테스트: 시나리오·질문지 초안을 만들고, 사용자가 붙여넣은 결과를 패턴으로 정리한다. 실제 사용자를 만나는 것은 사용자의 몫이다. 원문은 레포에 쓰지 않는다.

## 기본적으로 하지 않는 일
- 코드 직접 수정. 발견을 보고하고 고치는 것은 `/dev`에서 한다 (사용자가 지시하면 예외).
- `Done` 처리. 제안만 한다.

## 종료
`/wrap`으로 마무리한다. 위반이 있으면 상태를 `In progress`로 되돌리자고 제안한다.
