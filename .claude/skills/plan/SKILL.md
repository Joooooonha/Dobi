# 기획 세션 (대상: $ARGUMENTS)

`AGENTS.md` §1 절차로 시작한다 (읽기 → 4줄 브리핑 → 사용자 확인). 추가로 `docs/cbl.md`를 읽는다.

## 이 세션을 맡는 때
- 상태 `Draft`, 담당 `기획` (근거·범위 초안 작성 중). 코드가 아닌 기획 작업은 `Approved` 뒤에도 담당이 기획이다.
- 끝낼 때: 담당 → 디자인(설계가 필요한 spec). 기획 작업 자체가 끝났으면 `Done` 제안.

## 역할 확인 (시작 시 첫 단계)
1. `SPEC.md`에서 `현재 단계 담당`이 **기획**인 행을 찾는다. 인자가 있으면 그 행이 여기 해당하는지 확인한다.
2. 해당 행이 없거나 담당이 다른 세션이면 **작업하지 말고 멈춰서 알린다.** ("이 작업의 담당은 ○○입니다. `/○○`로 시작하세요.") 사용자가 지시하면 예외다.
3. 해당 행이 여러 개면 어느 것인지 사용자에게 묻는다.

## 역할
무엇을, 왜 만드는지 정한다. 사용자가 전달한 조사 자료에서 패턴을 뽑아 `docs/cbl.md`에 정리하고, 그 결론에서 spec Draft를 만든다.

## 하는 일
- §4.3: 질문마다 `근거(응답 수·패턴) → 결론 → 아직 모르는 것`을 분리해서 정리한다.
- **답을 미리 정하지 않는다.** 근거가 없는 결론은 '가설'로 표시한다 (cbl §8).
- spec Draft는 `docs/specs/00-template.md`로 쓴다. '근거' 줄이 비면 쓰지 않는다.
- 선택지가 갈리는 기획 결정은 ADR 후보로 남긴다.

## 기본적으로 하지 않는 일
- 기술·구조 선택, 코드 (→ `/design`, `/dev`)
- 설문·인터뷰 원문을 레포에 쓰기. 집계와 패턴만 쓰고, 역할·특성으로 개인이 특정되게 인용하지 않는다.

## 종료
`/wrap`으로 마무리한다 (상태 전이는 위 '맡는 때'의 '끝낼 때').
분량: 한 세션 = 결론 한 묶음 또는 spec Draft 하나.
