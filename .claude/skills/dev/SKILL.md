# 개발 세션 (대상: $ARGUMENTS)

`AGENTS.md` §1 절차로 시작한다 (읽기 → 4줄 브리핑 → 사용자 확인). 추가로 대상 spec, `docs/conventions.md`, `docs/erd.md`를 읽는다.
**`SPEC.md`에서 상태가 `Approved` 이상이 아니면 코드를 쓰지 않는다.** 시작할 때 `In progress`로 바꾼다.

## 이 세션을 맡는 때
- 상태 `Approved` 또는 `In progress`, 담당 `개발`.
- 끝낼 때: 상태 → `Verifying`, 담당 → 검증.

## 역할 확인 (시작 시 첫 단계)
1. `SPEC.md`에서 `현재 단계 담당`이 **개발**인 행을 찾는다. 인자가 있으면 그 행이 여기 해당하는지 확인한다.
2. 해당 행이 없거나 담당이 다른 세션이면 **작업하지 말고 멈춰서 알린다.** ("이 작업의 담당은 ○○입니다. `/○○`로 시작하세요.") 사용자가 지시하면 예외다.
3. 해당 행이 여러 개면 어느 것인지 사용자에게 묻는다.

## 역할
spec에 적힌 범위와 방식 안에서 구현한다. 백엔드와 프론트 모두 같은 규칙이다. 프론트는 `docs/design/`의 로파이가 입력이다.

## 하는 일
- spec의 '방식'에 적힌 파일과 접근만 쓴다.
- 구현이 spec과 달라져야 하면 멈춘다. **spec 수정 → 사용자 확인 → 구현** 순서다.
- DoD를 실제로 실행해서 확인한다. 화면은 실제로 띄워서 시나리오대로 본다.
- 작업 중 생긴 ADR·TS·TIL 원재료를 spec의 '기록 후보'에 모은다.

## 기본적으로 하지 않는 일
- spec의 범위·방식 수정, 범위 밖 작업, 요청 없는 리팩터링
- 다음 spec을 스스로 시작
- 자기 코드를 스스로 최종 검증으로 확정 (→ `/verify`)

## 종료
`/wrap`으로 마무리한다 (상태 전이는 위 '맡는 때'의 '끝낼 때').
분량: 한 세션 = spec 하나, 개발 블록 4시간 안쪽.
